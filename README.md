# 招新报名数据清洗与统计

协会每年招新会收到几百份报名表（问卷导出的 CSV）。这个小工具把这一堆表格
**体检 → 校验 → 清洗 → 统计**，全程只读原文件、结果另存，绝不覆盖报名原始数据。

> **交付说明**：三个需求分三次提交，对应 3 个 Pull Request（分支已按顺序堆叠好）。
> **零依赖**：只需要 Python 3.8+，不需要 `pip install` 任何东西。
> **数据安全**：不联网、不调用任何 AI 服务、不上传任何数据，全部在本机跑完。

---

## 30 秒跑起来

```bash
git clone <本仓库地址> && cd 招新报名数据清洗与统计

# 一键跑完三个需求（仓库自带示例数据，无需准备任何东西）
python run_all.py
```

跑完 `output/` 里就是全部结果。想分步跑：

```bash
python src/overview.py --input data/signup_raw.csv                  # 需求1 读入与概览
python src/validate.py --input data/signup_raw.csv -o output        # 需求2 校验与清洗
python src/report.py   --input data/signup_raw.csv -o output        # 需求3 统计与导出
```

### 换成你自己的报名表

```bash
# 问卷平台导出的 CSV 直接丢进来即可，文件名随意
python run_all.py --input "D:/downloads/2026招新报名表.csv" --output-dir "结果/"

# 如果你确定学号是 10 位，顺便把位数也校验上（默认不校验，原因见「假设」）
python run_all.py -i 报名表.csv --id-length 10

# 你协会的部门清单不是内置的那 8 个，就传进来（会用于「志愿填了清单外部门」的提示）
python run_all.py -i 报名表.csv --choices "项目开发部,品牌传播部,战略关系部,赛事运营部"
```

命令行参数一览：`python run_all.py --help`

## 校验规则明细

| 级别 | 问题类型 | 判定依据 | 处理 |
| --- | --- | --- | --- |
| 错误 | 必填项为空 | 姓名 / 学号 / 邮箱 / 志愿1 为空 | 剔除 |
| 错误 | 学号格式 | 学号不是**半角纯数字**（字母、连字符、空格、全角数字、Excel 带出的 `.0`） | 剔除 |
| 错误 | 邮箱格式 | 邮箱不含 `@`、含多个 `@`、含空格、非 ASCII 字符 | 剔除 |
| 错误 | 邮箱与学号不匹配 | 域名不是 `smbu.edu.cn`（含 `edu.com`、多 `stu.` 子域名、私人邮箱）；或前缀不等于学号 | 剔除 |
| 错误 | 重复报名 | 同一学号出现 ≥2 次 | 剔除多余提交（保留第 1 次） |
| 提示 | 两个志愿填成同一个 | 志愿1 == 志愿2 | 保留，清单里标注 |
| 提示 | 志愿不在部门清单内 | 志愿不在 `--choices` 指定的清单里 | 保留，清单里标注 |
| 提示 | 姓名疑似异常 | 姓名里混入数字或英文字母 | 保留，清单里标注 |
| 提示 | 学号位数 | 仅当显式传 `--id-length N` 时检查 | 默认只提示，`--strict-id-length` 升级为错误 |

**为什么分「错误」和「提示」两级**：需求原文只说「有问题」，但机器一刀切很容易误杀
（比如同学就是只想去同一个部门的两个小组）。所以把「必须联系同学更正」的判为**错误**
（挡在干净数据之外），把「可疑、需要人确认」的判为**提示**——提示级的行仍然算干净数据，
只是会在问题清单里被点名。

## 假设与边界情况

需求里没写死的地方，我一律做了显式假设。**如果跟协会的实际情况不符，改这几处即可。**

| # | 假设 | 为什么这么定 | 想改的话 |
| --- | --- | --- | --- |
| 1 | 字段就是这 6 列：姓名、学号、邮箱、志愿1、志愿2、推荐人 | 需求原文列出的字段 | `src/common.py` 的 `COLUMNS` |
| 2 | **必填 = 姓名、学号、邮箱、志愿1；选填 = 志愿2、推荐人** | 报名至少要能联系到人、至少要有个第一志愿；第二志愿和推荐人本来就允许空 | `src/common.py` 的 `REQUIRED_COLUMNS` |
| 3 | **不知道 SMU 学号是 8 位还是 10 位 → 默认不校验位数** | 位数校验错了一刀切会误杀几百行，属于「拿不准的边界」 | 加 `--id-length 10`（示例数据按 10 位 = 4 位入学年份 + 6 位序号生成），必要时再加 `--strict-id-length` |
| 4 | 邮箱**域名大小写不敏感**（`@SMBU.EDU.CN` 算对），前缀必须逐字符等于学号 | DNS 本身不区分大小写；但学号段错了就是真错了 | `src/validate.py` 的 `split_email` 比较逻辑 |
| 5 | `@stu.smbu.edu.cn` 这类**子域名算不匹配** | 要求原文是「邮箱必须是 学号@smbu.edu.cn」，逐字对应 | 同上 |
| 6 | 重复报名**保留第 1 次提交、剔除后续重复** | 人只来一次；第 1 次提交通常是最完整、最早的意向 | 加 `--drop-all-duplicates` 变成全部剔除 |
| 7 | **学号为空的重复不算「重复报名」** | 空学号已经在「必填项为空」里报过一次，再报重复是重复扣分 | `src/validate.py` 的 `find_duplicate_signups` |
| 8 | 需求1 的「完全重复行」= 所有字段逐字相同；需求2 的「重复报名」= 学号相同（其他字段可能不同） | 两个口径本来就是不同的东西，报告里分开统计 | — |
| 9 | 统计**默认基于清洗后的数据**（264 行），不是原始 290 行 | 汇总表要能直接用来分配面试，里面每个人都得是可联系、可录用的 | 加 `--keep-problems` 换成原始口径对比 |
| 10 | 占比分母 = 参与统计的人数；合计行固定 100% | 让表能直接贴进纪要 | — |
| 11 | 部门清单默认内置协会现行 **7 个部门**（创新创业部/项目开发部/课程研发部/综合行政部/品牌传播部/战略关系部/赛事运营部）；志愿填的是**部门**，不是中心 | 示例数据用；真实清单由你传 | `--choices "A,B,C"` |
| 12 | 「只填了一个志愿」= 志愿1 有值且志愿2 为空 | 志愿1 是必填，志愿1 为空的提交已经是错误行被剔除，不会出现在统计里 | — |
| 13 | 输出统一 UTF-8 with BOM | Excel / WPS 双击打开不乱码 | `src/common.py` 的 `OUTPUT_ENCODING` |
| 14 | 输入编码依次尝试 utf-8-sig → utf-8 → gb18030 | 问卷平台导出常见这三种 | `src/common.py` 的 `INPUT_ENCODINGS` |
| 15 | 不做的事：不联网、不上传、不改动输入文件、不自动删除任何行 | 报名表是原始凭证，工具只输出副本 | — |
| 16 | 「按中心汇总」按「部门 → 中心」映射归并（技术研发中心 / 运营管理中心 / 对外合作中心）；第一志愿不在映射里的人（留空、误填成中心名、乱填）归入「(志愿不在中心清单内)」并单独列一行 | 中心是上层归类、不作志愿选项；脏数据不静默丢弃，留人工确认归属 | `src/common.py` 的 `DEPARTMENT_CENTERS` |

**数据说明**：仓库里的 `data/signup_raw.csv` 是用 `tools/make_sample_data.py`
按固定随机种子（`SEED = 20260930`）**合成**的假数据，用来演示各种脏情况，
不含任何真实同学的个人信息。它埋了哪些坑、期望结论是什么，见
`data/sample_data_notes.md`。

按下面的顺序在 GitHub 上开 PR、合并，每个 PR 的 diff 就只包含本次需求的内容：

```bash
# 1）关联你的远端仓库
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
git push -u origin feat/01-overview feat/02-validate feat/03-report

# 2）在 GitHub 上依次创建 PR（base 都选 main），每开一个就合并一个：
#    ① feat/01-overview → main    （合并后再开下一个）
#    ② feat/02-validate → main
#    ③ feat/03-report   → main
#    每个 PR 的标题、说明、自测方式可以直接从 docs/PR-0x-*.md 里复制

# 或者用 GitHub CLI 一条条建（顺序执行，不要一次开三个）
gh pr create --base main --head feat/01-overview --title "feat(需求1): 读入 CSV 并打印概览" --body-file docs/PR-01-读入与概览.md
```

## 常见问题

**Q：我没有 Python？**
装 Python 3.8+ 即可（<https://www.python.org/downloads/>，Windows 勾选 “Add Python to PATH”），
不需要装任何第三方包。实在不想用命令行，把 `output/` 里的 CSV 直接拖进 Excel 也能看。

**Q：终端里中文是乱码？**
Windows 的 cmd 默认 GBK。用 Git Bash / PowerShell 跑，或先执行 `chcp 65001`。
导出的文件本身带 BOM，Excel 打开不会乱码。

**Q：想按原始数据（不剔除）统计一遍做对比？**
`python src/report.py -i 报名表.csv --keep-problems`，报告里会注明口径。

**Q：能不能顺便去重后自动给同学发邮件？**
不在需求范围内，也刻意没做——对外动作（发信）应当由人确认后再执行。

**Q：数据会上传到哪里吗？**
不会。整个工具只读本地 CSV、只写本地文件，没有网络请求，也没有任何 AI 调用。

## 关键实现说明

1. **统计口径写死在报告里**：默认基于**清洗后**的 264 行（剔除错误行、重复报名只留第 1 次）。
   一张汇总表要能直接拿去分配面试，里面每个人都得是可联系、可录用的。
   `--keep-problems` 可切回原始口径做对比，报告会注明用的是哪个口径。
2. **汇总表两种形态**：CSV（给后续处理）+ Markdown（直接贴进会议纪要），
   外加终端里的条形图，一眼看出哪个部门最热。
3. **双志愿填写情况四分类、互斥且加总 = 总人数**：
   两个都填 / 只填第一志愿 / 只填第二志愿 / 都没填。
   因为志愿1 是必填，清洗后「只填一个」实际等于「志愿2 为空」。
4. **干净数据带 `原始行号` 首列**：万一同学的邮箱需要人工核对，
   能顺着行号回到问卷导出的原始文件第几行。
5. **额外产出 `被剔除的行.csv` + 剔除原因**：清洗不是黑盒，
   每条被剔除的记录都写清了原因，方便人工复核或直接发给同学。
6. **幂等**：同一输入跑两次，产物逐字节一致（有测试守着），
   所以可以放心把 `run_all.py` 放进自动化里反复跑。
7. **报告里点名异常分组**：如果第一志愿里有不在部门清单内的值（如示例数据里的「电竞部」），
   报告会在汇总表下方提示「已标为提示，建议人工确认归属」，避免这些数字被当成正式部门。
